# مزونة — Mazona Furniture and Decor

موقع ساكن (Static) بدون خادم وبدون قاعدة بيانات، ومعاه لوحة إدارة (`/admin.html`) تتيح لك إدارة **المنتجات والتصنيفات والصور** مباشرة من المتصفح، بدون فتح GitHub يدويًا.

## كيف تشتغل اللوحة

اللوحة ملفات ساكنة (`admin.html` + `admin.css` + `admin.js`) — ماكو خادم خلفها. كل حفظ يروح لمستودع GitHub عبر **GitHub API**، وبعده يشتغل الـ workflow (`.github/workflows/deploy.yml`) تلقائيًا ويبني وينشر الموقع، بما فيه **sitemap.xml** (لأنه مبني من نفس `products.json`).

- **Commit واحد لكل عملية:** المنتج + صوره + ملف البيانات يُحفظون بـ Commit ذري واحد، فينتج **نشر واحد فقط** (مو نشر لكل صورة)، وما يصير أبدًا منتج بدون صوره أو صور يتيمة إذا انقطع النت بنص العملية.
- **آمنة مع التعديل المتزامن:** قبل كل حفظ تقرأ اللوحة أحدث نسخة من المستودع وتدمج عليها. لو أحد ثاني عدّل بنفس اللحظة، تعيد المحاولة تلقائيًا ولا تكتب فوق تعديلاته.
- **تنظيف الصور:** لما تحذف منتجًا أو تشيل صورة منه، الصورة تنحذف من المستودع بنفس الـ Commit (إلا لو منتج ثاني يستخدمها).

## الأمان

1. **الـ GitHub Token هو الحماية الحقيقية.** بدونه محد يقدر يحفظ شيء، مهما عرف الرابط. اللوحة تتحقق منه لحظة الدخول (وأنه يملك صلاحية كتابة على المستودع)، ويُحفظ بذاكرة التبويب فقط (`sessionStorage`) ويُمسح لما تسكر التبويب أو بعد **30 دقيقة عدم نشاط**.
2. **سياسة أمان المحتوى (CSP)** بالصفحة تمنع تحميل أي سكربت أو الاتصال بأي جهة غير GitHub API، وكل النصوص تُعرض كنص خام (لا HTML) — يحمي التوكن من حقن الأكواد.
3. **ما عاد فيه «كلمة مرور محلية»** — كانت تعطي إحساسًا بالحماية وهي بالواقع تُتجاوز بسهولة لأن الموقع ساكن. الدخول الآن بالتوكن نفسه.
4. خلّي الرابط `/admin.html` غير معلن (مو موجود بأي قائمة بالموقع، ومستثنى بـ `robots.txt` و`noindex`).

### كيف تسوي GitHub Token (مرة وحدة)

1. روح إلى: `github.com/settings/personal-access-tokens/new` (Fine-grained token)
2. **Repository access**: **Only select repositories** ← مستودع الموقع فقط
3. **Permissions ← Repository permissions ← Contents**: **Read and write** (ما تحتاج أي صلاحية ثانية)
4. حدد مدة صلاحية مناسبة، أنشئ التوكن وانسخه (ما يظهر مرة ثانية)

### أول استخدام

1. افتح `https://<نطاقك>/admin.html`
2. الصق التوكن. وإذا اسم المستودع غير الافتراضي (`mzunhkw` / `mzunhkw.github.io` / `main`) افتح «إعدادات المستودع» وعدّله.
3. تدخل مباشرة — والقيم تنحفظ بالمتصفح للمرات الجاية (التوكن نفسه لا).

## إضافة منتج

عبّي النموذج واضغط **حفظ المنتج**. النموذج يتحقق من كل حقل ويوريك الخطأ تحت الحقل نفسه.

| الحقل | ملاحظات |
|---|---|
| الرابط المختصر (slug) | حروف إنجليزية صغيرة وأرقام وشرطات فقط. يتولّد تلقائيًا من العنوان (أو `product-xxxxx` للعناوين العربية)، وتقدر تغيّره قبل الحفظ. **ما يتغير بعد الإنشاء.** |
| السعر | أرقام فقط، حتى 3 خانات عشرية. الأرقام العربية (٢٥٠) والفاصلة العشرية (٫) مقبولة. الفواصل (12,500) مرفوضة لأنها ملتبسة. |
| الصور | حتى 8 صور. اسحبها أو اخترها؛ تتحول لـ **WebP** وتُصغّر (أطول ضلع 1600px) قبل الرفع، وتشوف حجمها النهائي. أول صورة = **الغلاف**، وتقدر تقدّم/تأخّر/تحذف كل صورة. |
| مميز | يظهر بقسم «مختارات» بالرئيسية. |
| منشور | إذا ما هو مؤشّر يبقى **مسودة**: محفوظ باللوحة ولا يظهر بالموقع. |

المنتج الجديد يُضاف **أول القائمة**.

### حالات المنتج وأثرها على الموقع

| الحالة | يظهر بالموقع؟ |
|---|---|
| متاح للتفصيل / قطعة جاهزة | نعم |
| غير متاح مؤقتًا | نعم، مع وسم «غير متاح مؤقتًا» |
| مؤرشف | **لا** — يختفي من القوائم وصفحة المنتج والـ sitemap |
| غير منشور (مسودة) | لا |

### إدارة المنتجات

من قائمة المنتجات: **تعديل** · **نسخ** (ينسخ البيانات كمسودة بدون الصور — مفيد للمنتجات المتشابهة) · **إخفاء/نشر** (بضغطة وحدة) · **عرض** (يفتح صفحة المنتج) · **حذف**. فيه بحث وفلترة بالتصنيف والحالة.

## التصنيفات

من تبويب **التصنيفات**: إضافة، تعديل الاسم، إعادة الترتيب (نفس الترتيب يظهر بالموقع)، وحذف. لا يمكن حذف تصنيف فيه منتجات. الـ slug ما يتغير بعد الإنشاء لأن المنتجات تشير له.

## فحص البيانات قبل النشر

`npm run build` يشغّل تلقائيًا `scripts/validate-data.mjs` قبل البناء: يفحص التصنيفات والمنتجات (slug فريد، تصنيف موجود، سعر صحيح، ملفات الصور موجودة…). لو فيه خطأ **يفشل البناء بدل ما ينشر موقع مكسور**، وتبقى النسخة المنشورة الحالية شغّالة. تقدر تشغّله يدويًا: `npm run validate`. (اللوحة نفسها تطبق نفس القواعد قبل الحفظ، فالمفروض ما تشوف هذا الفشل إلا لو عدّلت الملفات يدويًا.)

## تشغيل المشروع محليًا (اختياري، للمطورين)

```
npm install
npm run dev
```
يفتح على http://localhost:3000 — واللوحة على http://localhost:3000/admin.html (بترفع فعليًا للمستودع الحقيقي حتى وأنت شغّال محليًا، لأنها تتكلم مباشرة مع GitHub API).

## إعداد GitHub Pages (مرة واحدة عند إنشاء المستودع من جديد)

1. Settings → Pages
2. Source: اختر **GitHub Actions** (مو "Deploy from a branch")
3. أول Push لفرع main يشغّل البناء والنشر تلقائيًا

إذا عندك نطاق مخصص (مثل mazunhkw.com)، أضف ملف `public/CNAME` يحتوي على النطاق فقط، وحدّث `siteUrl` بملف `src/data/site-config.ts` لنفس النطاق (يُستخدم بالـ sitemap).


## السيو (SEO)

- **صفحات أقسام مستقلة** `/category/<slug>/` لكل تصنيف (كنب وقنفات، مجالس، مساند…) بعنوان ووصف ونص تعريفي وأسئلة شائعة. النصوص بـ `src/data/category-seo.ts` (المفتاح = slug التصنيف)، وأي تصنيف جديد بدون نص يأخذ نصًا عامًا تلقائيًا.
- **بيانات منظمة (JSON-LD):** متجر أثاث (العنوان/الدوام/الهاتف)، ومسار تنقل (Breadcrumb) لكل الصفحات، وبيانات منتج (السعر بالدينار الكويتي) لكل منتج.
- **Canonical** لكل صفحة، وصفحة `/products/` هي المرجع لروابط `?category=…`.
- **sitemap.xml** يشمل الرئيسية والأقسام وكل المنتجات الظاهرة، و`robots.txt` يشير له ويستثني `/admin.html`.
- **ربط داخلي:** أقسام المعرض بالرئيسية والتذييل، ومسار تنقل بصفحة المنتج، وقسم «قطع أخرى من نفس التصنيف».

**بعد النشر:** سجّل الموقع بـ Google Search Console وأرسل `https://mazunhkw.com/sitemap.xml`، وأنشئ ملف نشاط تجاري بـ Google Business Profile للمعرض (الضجيج — مجمع علي عبدالوهاب). وأهم شيء للترتيب: صور حقيقية لكل منتج، وعنوان ووصف واضحين (مثال: «كنب ركنة رمادي 3 مقاعد»).
